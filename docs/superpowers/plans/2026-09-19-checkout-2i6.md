# Checkout 2I-6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the public package-selection and checkout flow so a new user selects an ACTIVE package, registers an account and store, then creates a PENDING bank-transfer payment using the package price snapshot.

**Architecture:** Keep package management as the source of truth in `packages`. Carry only the selected package ID through registration, validate it server-side, create account/store atomically, then show checkout from the authenticated session and re-read package data before inserting `payments`. The checkout scope ends at payment creation with status PENDING.

**Tech Stack:** PHP 8.3+, MySQL/MariaDB, PDO prepared statements, existing RESTOCK session/auth conventions, Tailwind CDN and existing app.css.

**Spec:** Validated in chat on 2026-09-19: flow is `Pilih Paket → Daftar → Buat Toko → Checkout → payments(PENDING)`; no proof upload, verification, subscription activation, or bank-account settings in 2I-6.

## Global Constraints

- Package prices must never be hard-coded in public checkout code.
- Only packages with `status = 'ACTIVE'` may be selected for a new registration.
- The server must re-query and validate the selected package; URL/session values are not trusted as price data.
- `payments.amount` stores the checkout-time package price snapshot.
- `payments.payment_method` is `BANK_TRANSFER` and initial `status` is `PENDING`.
- Account/store creation remains transactional and must not leave partial registration records.
- Use CSRF protection for all state-changing POST requests.
- Use PDO prepared statements with unique named placeholders.
- Escape displayed database/user values with `htmlspecialchars`.
- Do not add a database migration for 2I-6.

### Task 3: Checkout Payment Creation

**Files:**
- Create: `checkout.php`
- Create: `tests/test_checkout.php`

**Interfaces:**
- Consumes: authenticated `account_id`, `store_id`, and `selected_package_id` from session.
- Produces: one `payments` row with `payment_method = 'BANK_TRANSFER'`, `status = 'PENDING'`, and the current package price in `amount`.

- [ ] **Step 1: Write the failing test**

Create a static contract test requiring `checkout.php` to authenticate the user, read account/store/package session values, re-query the package from `packages`, use an INSERT into `payments`, set BANK_TRANSFER and PENDING, populate `expired_at`, and never trust a submitted price.

- [ ] **Step 2: Run the test to verify it fails**

Run:
`php tests/test_checkout.php`
Expected: FAIL because `checkout.php` does not exist.

- [ ] **Step 3: Implement checkout GET**

Require the existing authenticated user/store session. Re-query the package using:
`SELECT id, name, slug, price, duration_days, description FROM packages WHERE id = :package_id AND status = 'ACTIVE' LIMIT 1`

If the selected package no longer exists or is inactive, clear `selected_package_id` and redirect to `/paket/`.

Display package name, duration, description, and server-read price. The form contains only a CSRF token and payment-method selection fixed to BANK_TRANSFER.

- [ ] **Step 4: Implement checkout POST**

Verify CSRF. Ignore any posted price. Re-query the package again using the same ACTIVE query. Insert:
`INSERT INTO payments (account_id, store_id, package_id, amount, payment_method, status, expired_at, created_at, updated_at) VALUES (:account_id, :store_id, :package_id, :amount, 'BANK_TRANSFER', 'PENDING', :expired_at, CURRENT_TIMESTAMP, CURRENT_TIMESTAMP)`

Use the package price returned by MySQL for `:amount`. Set `:expired_at` to 24 hours after checkout. Use unique named parameters.

After successful insert, store `payment_id` in session and redirect to `/checkout.php?success=1`.

- [ ] **Step 5: Add duplicate-submit protection**

If `$_SESSION['payment_id']` already references a PENDING payment for the same account/store/package, do not create a second payment. Show the existing pending payment state instead. This prevents accidental double-clicks from creating duplicate bills.

- [ ] **Step 6: Run the checkout contract test**

Run:
`php tests/test_checkout.php`
Expected: PASS when runtime PHP is available.

- [ ] **Step 7: Commit**

`git add checkout.php tests/test_checkout.php && git commit -m "feat(checkout): create pending bank transfer payment"`
